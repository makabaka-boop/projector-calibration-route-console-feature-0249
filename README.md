# 穹幕投影机校准 · 精确路线台

穹幕投影机校准时需要把**全部姿态（1…N）各测量一次**，镜组在姿态之间转动的耗时
**有方向性**（`C[i→j] ≠ C[j→i]`，非对称）。凭经验排序会浪费宝贵的停机窗口。

本工具给出：

1. **编辑与导入台**：维护 `(N+1)×(N+1)` 的非对称费用矩阵，严格校验，坏数据整批拒绝、
   旧计划保留；
2. **精确路线候选集**：从停放位 `0` 出发，每个姿态恰好访问一次并回到 `0`，一次求解给出
   **按总耗时升序、同费按姿态序列字典序升序的前三条互异精确路线**，逐条显示排名、
   总耗时与完整路径；默认选择首名（即字典序最小的精确最优），工程师可改选任意一条
   后进入执行台；
3. **现场执行台**：以**所选候选**为原计划与增量基线。工程师可把**任一未完成姿态**确认为
   实际下一站（随时偏离原路线），页面累加已发生费用，并**以该姿态为新起点对全部剩余
   姿态精确重排**，给出最短收尾路线、预计完工耗时及相对所选基线的增量；已完成姿态
   立即禁用，不能再次确认。

> 求解器是 **Held–Karp 动态规划**，精确最优——**不是贪心，也不是全排列枚举**。
> 候选集也不是“禁用首选路线的边反复重解”，而是把每个 DP 状态从单个最优值扩展为
> **固定三名不同后缀及其子排名**，一次递推全部得出。
> 所有计算都在浏览器本地完成；**数据只留在浏览器**（`localStorage`），没有任何后端 API。

## 适用范围与硬性规则

| 项目 | 规则 |
| --- | --- |
| 姿态编号 | `1…N`，`N` 取 **8—18** 的整数；`0` 为停放位 |
| 费用矩阵 | `(N+1) × (N+1)` 方阵，行优先二维数组，`matrix[i][j]` = 从 `i` 转到 `j` 的耗时 |
| 主对角线 | **必须为 0**（编辑器中锁定，不可改） |
| 非对角项 | **1—9999 的整数**（有方向性，不要求对称；小数、负数、缺项等一律拒绝） |
| 整批拒绝 | 任一缺项、越界、形状不符、类型错误 → **整批拒绝并保留旧计划**，错误就地显示 |
| 目标 | 从 `0` 出发，每个姿态恰一次，回到 `0`，总耗时最小 |
| 候选集 | 一次求解给出**前三条互异精确路线**：按总耗时升序、同费按完整姿态序列字典序升序；可行路线不足三条时只返回实际数量，不占位、不重复 |
| 选择与基线 | 默认选择首名（字典序最小的精确最优），工程师可改选；执行台以**所选候选**为原计划与增量基线；应用新矩阵时旧候选与选择一起失效并重算 |
| 性能 | **N=18 精确求解 < 4 秒**（本机实测：单最优约 130—150 ms，前三候选集约 500—600 ms；现场每拍重排随剩余数递减，更快） |

支持的 JSON 形态（含数字与数组，工程师可手工编辑或导入）：

```json
{
  "n": 8,
  "matrix": [
    [0, 12, 7, 33],
    [9, 0, 41, 5],
    [7, 38, 0, 11],
    [30, 6, 14, 0]
  ]
}
```

- `matrix` 也可写成 `costs`；
- 也接受**裸二维数组**，此时 `N = 边长 - 1`；
- 文件导入（`.json`）与文本框粘贴等价，先入草稿，**校验通过后点“校验并应用”才生效**。

## 算法说明（为什么是精确解，且字典序最小）

定义（`src/solver/tsp.ts`）：

```
g[mask][i] = 从 target[i] 出发，恰好访问 mask 中全部目标（i 不在 mask 内），最后回到 0 的最小耗时
g[0][i]    = C(target[i] → 0)
g[mask][i] = min_{j ∈ mask} C(target[i] → target[j]) + g[mask \ {j}][j]
```

答案：`min_i C(0 → target[i]) + g[full \ {i}][i]`。

- 时间复杂度 `O(m²·2^m)`，空间 `O(m·2^m)`；m=18 时约 470 万个 DP 单元、约 500 万次转移，
  使用 `Int32Array` 紧凑存储，亚秒级完成。
- **字典序 tie-break**：目标按编号升序排列，恢复路线时在每一位上从小编号到大枚举，
  选“仍能达到全局最优总耗时”的第一个候选。这样逐位选择得到的就是字典序最小的最优序列，
  且与全排列基准（按字典序生成、严格小于保留首个最优）逐组核对一致。
- **现场重排**只是把 `origin` 从 `0` 换成刚确认的姿态、目标集合换成剩余姿态再解一次；
  每一拍得到的后缀都是该状态下的全局最优后缀，因此每次现场改序仍有**最短收尾路线**。
- 预计完工 = 已发生费用 + 当前最优后缀（含返回 `0` 的边）；
  增量 = 预计完工 − 原计划基线。基线是所选候选：选首名（精确最优）时增量恒 `≥ 0`；
  **改选次优候选时增量允许为负**——因为每一拍仍按精确最短后缀重排，实际完工可能
  优于所选的次优路线。

### 候选集：每个状态扩展为固定三名不同后缀

`solveTopCandidates` 把每个 DP 状态从单个最优值扩展为 **TOP_K = 3 个互异后缀及其子排名**：

```
best[mask][i][r] = 状态 (mask, i) 的第 r+1 好互异后缀耗时（r = 0..2）
pick[mask][i][r] = 该后缀的首步指针 j*3+r′（接 best[mask\{j}][j][r′]）
```

- 递推时把每个 `j ∈ mask` 的子状态前三名按 **(总费用, j 升序, 子排名升序)** 归并取前三；
  该比较键与“总耗时升序、同费按完整姿态序列字典序升序”的全局排序键等价
  （同费先比首姿态编号，同首姿态时子序列顺序即子排名顺序）。
- k-best 最优子结构：若某后缀的子后缀落在子状态前三之外，则至少已有三条完整后缀
  排在它前面，故每个状态只保留三名即可精确恢复全局前三。
- 存储保持紧凑：`best` 用 `Int32Array`、`pick` 用 `Uint8Array`（m=18 约 57 MB + 14 MB）；
  恢复路线只沿 `pick` 指针走，完全确定，不再搜索。
- 候选首名与 `solveOptimal` 完全一致（费用与序列均相等），既有现场后缀重排逻辑不变。

产品代码中**没有**贪心近似，也**没有** `m!` 枚举；全排列枚举只存在于测试基准
（`src/solver/brute.ts`，含 `bruteForceTopK` 前三名预言机），用于穷举小样本核对精确值。

## 本地开发

```bash
npm install
npm run dev        # 开发服务器 http://localhost:5173
npm run build      # 类型检查 + 生产构建到 dist/
npm run preview    # 预览生产构建
npm run test       # Vitest 一次性运行
npm run verify     # 同 test，供 Docker verify 服务调用
```

要求 Node.js 20+。

## Docker Compose

多阶段 `Dockerfile`：

- `web` 阶段：构建静态产物并用 **nginx** 发布（纯静态，无后端）；
- `verify` 阶段：装依赖后执行 `npm run verify`，**一次性**，退出码即验收结论。

### 发布页面（端口可用 `WEB_PORT` 覆盖）

```bash
# 默认 8080
docker compose up -d --build web
# 打开 http://localhost:8080

# 覆盖端口
WEB_PORT=9000 docker compose up -d --build web
# 或复制 .env.example 为 .env 后修改 WEB_PORT
```

### 一次性验收

```bash
docker compose --profile verify run --rm verify
```

`verify` 挂在 `verify` profile 下，不会随 `docker compose up` 启动，也不会被重启；
跑完穷举核对与 N=18 性能指标后容器退出。

## 数据与隐私

- 已生效计划只写入当前浏览器的 `localStorage`（键 `dome-calibration-plan-v1`），
  加载时重新校验，损坏数据自动回退默认计划。
- 应用本身不发起任何网络请求（无 `fetch` / XHR / WebSocket / 埋点）；
  部署形态是 nginx 静态文件。清空站点数据或点击“恢复默认计划”即可删除本地数据。

## 项目结构

```
src/
  solver/
    plan.ts        # 数据模型 + 严格整批校验
    tsp.ts         # Held–Karp 精确求解（Int32Array，字典序 tie-break）+ 前三候选集（每状态三名后缀）
    execution.ts   # 执行状态机：开始（可选候选基线）/ 确认下一站并精确重排 / 回库（纯函数）
    brute.ts       # 仅测试用：全排列穷举基准 + 前三名预言机 + 可复现随机矩阵
    *.test.ts      # 穷举核对、候选集核对、逐步偏离验收、校验边界、N=18 性能
  components/
    MatrixEditor.tsx     # N 选择、逐格编辑、JSON 导入/导出、就地错误
    ExecutionConsole.tsx # 指标卡、路线、姿态确认、回库、最终台账
    components.test.tsx  # UI 行为测试
  state/storage.ts       # localStorage 读写（再校验后才落盘）
  App.tsx                # 编辑台（候选集选择）/ 执行台页签
Dockerfile  docker-compose.yml  nginx.conf  .env.example
```
